# 编码规则

## 基本要求

1. 项目统一使用中文编写规则说明、设计约束与协作约定。
2. 默认使用 C++17 标准进行开发，新增代码必须兼容 C++17。
3. 代码应优先保证可读性、可维护性与类型安全，避免为追求技巧而增加理解成本。
4. 修改代码时应遵循最小改动原则，不得无关重构。

## C++ 开发要求
critical：开发前先阅读coderule.md和arch.md，确保理解并遵守其中的编码规范与设计原则。每次更改了目录结构都有更改arch.md，说明你对目录职责有了新的理解，这时需要更新arch.md来反映你的理解，以便团队成员保持一致。

## 实现与质量要求

1. 条件分支、循环与错误处理必须保持清晰，禁止过深嵌套；必要时拆分函数。
2. 单个函数应尽量只完成一件事，函数长度应控制在便于审查和维护的范围内。
3. 注释应解释设计意图、边界条件与约束，不得重复代码表面含义。
4. 所有新增代码应避免未定义行为、空悬引用、越界访问与未初始化读取。
5. 面向接口编程时，应优先保证异常安全、资源释放安全与线程安全边界清晰。
6. 测试代码、示例代码与正式代码应保持同样的命名与结构规范。

## 提交前检查

1. 确认新增与修改代码符合 C++17 要求。
2. 确认文件组织符合 `.c/.h` 分离规则。
3. 确认类定义已放入头文件。
4. 确认命名均符合驼峰命名法。
5. 确认无明显死代码、无意义注释与调试遗留。
